## Acronyms

- **CFM** = Customer Fund Management (PG&E business unit)
- **FTS** = File Transformation Service
- **KDF** = KUBRA Data Format
- **TD(s)** = Transaction Division(s) — merchant identifiers configured within payment processors (Chase Paymentech, PayPal, NACHA/US Bank) that define processing/settlement rules for a given client
- **CPT** = Chase Paymentech (aka Chase Merchant Services/CMS, aka Chase Payment Solutions)
- **FTI** = Fund Transfer Instructions
- **PBO** = Payment Batch Orchestrator — KUBRA coordination service that creates payment batches and orchestrates export/import of batches and bundles to settle transactions with payment processors (Chase Paymentech, Fiserv/CheckFree, FMS Nashville, PayPal, NACHA, etc.); manages batch IDs, settlement reconciliation, remittance timing, and the reconciliation handshake between the platform and billing-and-payment (expansion confirmed from EP-016 notes) — variant: "PB1" (mishearing, noted 7/14)
- **IRN** — unknown expansion; Vitalii's own guess is "intelligent receipt number," unconfirmed
- **CPG** — unknown expansion; referenced by Jaro re: eLockbox setup
- **DSO** = DevSecOps (a REPAY shared service group)
- **DNIS** = Dialed Number Identification Service — a feature within IVR+
- **IVR+** = KUBRA HQ product — variant: "IBR plus" (mishearing)
- **PD(s)** = Payment Division(s) — synonymous with TD(s) Transaction Division(s)
- **BP** = Billing & Payment (legacy platform schema) (skill-proposed, approved)
- **PINT1** = Jira project owned by the Payment Integration Team 1 team, co-led by Miso Sipicki and an unconfirmed second lead; responsible for the Payment Intent API, Payment Transaction API, and Payment Response Consumer, plus additional calls to the PAN Validation API, PayGuard, etc. as part of capturing a payment
- **MOP** = Method of Payment (assumed expansion, skill-proposed — flag if incorrect)
- **ACH** = Automated Clearing House
- **TKD** = Technical Discovery — Jira project key used by the Katalyst Technical team (added 2026-07-15)
- **10 DLC** = 10-Digit Long Code — Twilio SMS campaign type; suitable for under 200,000 SMS/day; ~1 hour to set up with Todd Clement's Twilio contact
- **DKIM** = DomainKeys Identified Mail — email authentication standard; clients need DKIM DNS entries set up before KUBRA can send email from their domain — variants: "DKM", "beim"
- **SPF** = Sender Policy Framework — email authentication standard (alongside DKIM)
- **NSG** = Network Security Group — KUBRA internal security/network team; manages SFTP credentials and API key security
- **SOW** = Statement of Work
- **RACI** = Responsible, Accountable, Consulted, Informed — responsibility assignment matrix used in phase/stage documentation
- **RCP** = Retail Cash Payments (heard as "ECP" in transcript — Vitalii Djiguir: "B HQ or uh my HQ or ECP for that matter")
- **QBR** = Quarterly Business Review
- **BRD** = Business Requirements Document
- **MOU** = Memorandum of Understanding

## Jargon / Team-specific terms

- **"memo file"** = micro-batch pending-payment file, runs 8PM for payments up to 3PM cutoff
- **"tailing query"** = query using the last processed record's sequential ID as a checkpoint marker
- **"delta file"** = file containing only new/changed records since the last run
- **"Jira board"** = the team's Jira/swarm tracking board (heard as "Jerboard" in the 7/14 meeting)
- **"Client funded model"** = new functionality that a specific client pays to have built, as distinct from platform/product-funded work
- **"Revoke All Consent Act"** = US law already signed; effective January 31, 2027; an SMS opt-out (STOP) from a consumer applies across all products sharing the same sender short-code or long-code — flagged by Todd Clement as requiring near-term platform response
- **"phrasebook"** = platform's locale key→display text lookup system; used to resolve label keys into locale-specific strings for extension fields and payable option labels
- **"PGETFM"** = Vitalii Djiguir's informal shorthand for PG&E CFM (seen in transcript 2026-07-24)
- **"select one" / "select many"** = extension field data types for single-select and multi-select option fields; settled terminology in design discussions
